# D29 — `doctor` reported `[ok]` on the pinned-image check when the digest did not match

**Step:** launch pass, section D3 (systematic-breaker agent). **Date:** 2026-08-12.
**Status:** fixed, validated. **Raw:** `src/cytune/doctor.py::_check_image`.
Repro: `CYTUNE_SANITIZER_IMAGE=localhost/motifbo-env:phase0 cytune doctor`.

## Summary

```
[ok  ] pinned image     localhost/motifbo-env:phase0 (3bbe69a1d8f8… != expected d45e33b08bad…)
READY, with 1 degraded guarantee(s)
```

`_check_image` returned `ok=True` for **any image that exists**, appending the mismatch to the
label rather than to the verdict. The `[ok]/[warn]` column is the entire point of `doctor` — it is
what a user scans — and the row that owns the pinning claim gave the wrong answer on precisely the
condition that makes results incomparable.

The same code path means a locally rebuilt `motifbo-env:phase1` with a different digest reads
`[ok] pinned image`.

## Fix

A digest mismatch is now `DEGRADED, ok=False`, with a fix line that says what it costs — your
numbers are not comparable with the published ones, nor necessarily with your own earlier runs —
and points at `doctor --build-image`, which verifies the digest and refuses if it differs.

## Validation

Correct image → `[ok]`, `READY — all checks pass`. The breaker's exact repro →
`[warn] pinned image … NOT the pinned d45e33b08bad…`, counted as a degraded guarantee.

## Not fixed, recorded

`_check_image` inspects `sanitize_gate.IMAGE`, which `CYTUNE_SANITIZER_IMAGE` overrides, rather than
`rig.IMAGE`, which is what actually builds and measures. So the row can report on an image the run
will never use. The separate `sanitizer gate` row does check by digest and degrades, so the summary
is not a clean pass — but the two rows are answering about different images and neither says so.

## Class

**"The label carried the finding and the verdict did not."** A user scanning a column of `[ok]`
learns nothing from text appended after it.
