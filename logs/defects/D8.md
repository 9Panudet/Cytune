# D8 — driver ignored the template's dtype parameter; float-dt fleet variants failed every call

**Step:** P-2 synth stage, slot 13 retry (`fleet_FLAT_FM_13_fm_dot_r1`). **Date:** 2026-07-17.
**Status:** fixed (code-validated); first in-fleet float-dt kernel confirms on relaunch.
**Commits:** c7f402d (fix + pre-guard), 5e7c4e5 (attempt-numbering stability).
**Raw:** `results/fleet/run_fleet.log` — `ValueError: Buffer dtype mismatch, expected 'float' but
got 'double'` at kernel.pyx:6 during calibrate's reference measure; MEASURE_FAIL entry in
`results/fleet/fleet_ledger.jsonl`.

## Summary

`_drv_two_arrays` (the driver builder for all six FLAT_FM templates) hardcoded
`.astype(np.float64)` while the pyx templates parameterize the memoryview dtype (`{dtype_c}` —
`double` or `float`). Any float-dt instance crashed on EVERY kernel call, so calibrate's reference
measure failed and the runner ledgered MEASURE_FAIL after a full 1728-config build (~25 min
wasted per occurrence, and it would have recurred on every float variant across the fleet).

## Root cause

The driver-builder calling convention didn't carry the instance's parameter dict, so per-instance
dtype could not reach the drivers; the one template that needed dtype earlier (`int_horner32`)
worked around it with a hardcoded lambda kwarg, hiding the gap. Same defect class as D7
(producer/consumer contract miss): the compile smoke builds every template but never CALLS one,
so a call-time dtype mismatch was invisible.

## Fix

1. `emit_kernel` forwards `params` to every driver builder; `_drv_two_arrays` maps
   `dt → np.float32/np.float64`; two registry lambdas with positional-arg collisions moved to
   keyword arguments. TDD: emitted float-dt driver must contain `float32` when the pyx declares
   `float[::1]`.
2. **PARAMS_DUPLICATE pre-guard**: a candidate whose (template, params, trap) exactly matches an
   ACCEPTED kernel (guaranteed anti-clone rejection) or a prior REJECTED_CLONE attempt (measured
   evidence exists) skips its ~1 h measure; dup-skips consume the attempt number so the
   kid↔params mapping is stable across relaunches (a skipped attempt can never hand its output
   dir to a different parameterization). The measured anti-clone check remains the authority for
   every novel parameterization.
3. Record correction: two earlier commit messages mislabeled slot-12's accepted `_r1` as
   "float32" — it was double/L3; the ledger's per-entry params were always authoritative.

## Validation

13 harness tests green in X′ (dtype-match, pre-guard incl. both statuses, attempt-consumption via
review); fleet confirmation = slot-13 relaunch: L1-double attempt skipped as PARAMS_DUPLICATE,
float/L3 re-emitted with the fixed driver and measured through finalize.

## Lesson

Extends D7's rule: the generator smoke must not only drive one kernel through the full consumer
chain, it must do so for one instance of EVERY parameter AXIS that changes an interface (dtype,
signature, arg count) — parameter re-skins that alter the ABI are new contracts, not new values.
