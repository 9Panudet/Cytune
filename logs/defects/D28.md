# D28 — an edited kernel silently reused the previous kernel's calibrated workload

**Step:** launch pass, section D3 (systematic-breaker agent). **Date:** 2026-08-12.
**Status:** fixed, validated. **Found by:** a **breaker agent**, stability-matrix cell 2c
(source edit into a reused workspace).
**Raw:** `src/cytune/session.py::invalidate_stale_builds`, `::reusable_knob`, `cli.py:264,296`.

## Summary

The narration contradicted itself eight lines apart, in the same run:

```
 9:  cache invalidated because the module source changed — discarding 25 cached build(s) …
17:  reusing the calibrated REPS = 105 from the previous run
     (module, driver, --target-ms, image and rig are unchanged)
```

The user asked for a 5 ms reference. They got **23.3 ms**, and the certificate still recorded
`target_ms: 5.0, provenance: "command line"`.

## Root cause — an ordering bug, not a logic bug

`invalidate_stale_builds` (cli.py:264) ends with `self._merge_key(key)`, writing the **new** module
hash into `cache_key.json`. `reusable_knob` (cli.py:296) runs afterwards and compares the new key
against the record that line just overwrote. It therefore **always matched**, for any edit.

`reusable_knob`'s own docstring is correct about what calibration depends on — module, driver,
target_ms, image, rig mode. The comparison was simply made against a record that had already been
updated to agree.

## Why it matters more than it looks

This is the **normal edit-then-retune loop**. Two certificates from the same workspace would report
the same `target_ms` and describe different workloads, and the reference is the denominator of every
speedup in the document.

## Fix

`invalidate_stale_builds` now drops `knob_value` when it invalidates: calibration is a property of
the module, the module changed, so it is stale by its own definition. Recorded as
`invalidated_calibration` on the returned record, and the CLI says so instead of claiming the module
is unchanged.

## Validation

Live: after a source edit into the same workspace, the run re-calibrates and no longer prints the
"unchanged" line. 29 cache tests pass; 769 in the suite.

## Class

**"A comparison made against a record the caller has already updated."** Distinct from the I3 family
it lives beside: the invalidation logic was right, and it ran before the thing that consumed it.
