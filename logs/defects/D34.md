# D34 — two gates keyed on a directory a branch switch cannot empty, one failing open and one failing shut

**Step:** launch closeout, step 5 (re-run the live smoke gate). **Date:** 2026-08-13.
**Status:** both fixed, both validated (each ran red before and green after, in the state that
produced it).
**Found by:** re-running `smoke.sh` for the closeout, and then running `pytest -q src/cytune` on
`main` — that is, by executing the two gates on a branch other than the one they were written on.
**Raw:** `scripts/release/smoke.sh:38`, `src/cytune/test_cytune_vendor.py:310`,
`results/fleet/FREEZE_MANIFEST_V2.json`, `results/fleet/SANITIZER_INFEASIBLE_OVERLAY.json`.
Recompute: `bash scripts/release/smoke.sh` on `dev` · `pytest -q src/cytune/test_cytune_vendor.py`
on `main`.

## Summary

One root cause, found twice in an hour, in opposite directions.

**A checkout does not tidy up.** Git deletes the *tracked files* a branch does not carry and leaves
the *directory* behind whenever anything untracked is still inside it — a `__pycache__`, a build
cache, an ignored artifact. So after `git checkout main`:

```
$ ls -a scripts/phasep
.  ..  __pycache__
```

`scripts/phasep` still exists. It contains none of the study code. Every gate that asks *"is the
tree here?"* by asking *"does the directory exist?"* now gets the wrong answer, and which failure it
produces depends only on which way the condition was written.

| | the check | what a branch switch did | direction |
|---|---|---|---|
| **B1 fleet gate** | `[ -f results/fleet/FREEZE_MANIFEST_V2.json ]` in `smoke.sh` | deleted the file (force-added on `research` only) → `else` branch | **failed open** — printed `NOT RUN` and the gate passed without running |
| **vendor drift guard** | `os.path.isdir("scripts/phasep")` in `test_cytune_vendor.py` | deleted the files, kept the directory | **failed shut** — demanded ten files that are not supposed to be on this branch |

The second one is the reason the first was believable for as long as it was: a false failure gets
looked at within seconds, and a false pass is a yellow line in a wall of green.

## B1 — the fleet gate had not run on `dev`

`smoke.sh` step 0 guards the fleet replay on the presence of one freeze artifact. Both artifacts it
actually needs — `FREEZE_MANIFEST_V2.json` (71 KB) and `SANITIZER_INFEASIBLE_OVERLAY.json` (16 KB) —
had been force-added to **`research` only**, so a checkout of `dev` removed them and the gate
degraded to:

```
NOT RUN  B1 fleet gate — results/fleet is absent on this branch.
         Run it on `dev` or `research` before tagging. A gate that cannot run here has NOT passed here.
```

printed **while on `dev`**. The message names the branch it is failing on as one of the places to go
instead. And the wording invites exactly the wrong inference: *"absent on this branch"* reads as a
property of the branch layout, when the truth was that two 88 KB files had been deleted from the
working tree ten seconds earlier.

What that cost: `dev` is where engine changes are made, and B1 is the gate that exists **because the
nine live anchors are validation and not coverage** — it caught a 516 % worst case that reached 58 of
149 fleet kernels and **0 of 9 anchors**. It could not run on the branch it was built to protect.

*Fixed:* both manifests are force-added to `dev`; `smoke.sh` tests for **both** files; the NOT-RUN
message now says to check for a deleted file before believing the branch. B1 then ran, on `dev`:
149 kernels × 9 budgets, every cell byte-identical to the committed baseline.

## The vendor drift guard — a false failure on `main`

`test_the_drift_check_is_not_vacuously_skipping` exists to stop TIER-2 comparisons skipping
silently. It skipped on `os.path.isdir(STUDY)` and asserted otherwise, so on `main` it took the
assert branch on the strength of an empty directory:

```
AssertionError: the study tree is present but these mapped sources are gone:
['scripts/phasep/theta.py', 'scripts/phasep/build.py', ...]
```

*Fixed:* it keys on whether any **mapped source** exists, not on the directory, with an anti-vacuity
assert that the mapping itself still has entries — because a mapping that emptied out would make
both branches trivially true and restore the exact vacuity this test was written to prevent.

## Root cause

`os.path.isdir(d)` and `[ -f f ]` are not the questions either gate meant to ask. The question is
*"is the thing I need to compare against actually here?"*, and the only honest way to ask it is to
look for the thing.

Underneath that is the branch model itself: `main` is derived from `dev` by removal, `results/` is
ignored on both, and the tracked-past-the-ignore-rule set differs per branch. That design is
deliberate and documented (`docs/system/15_BRANCH_HAZARD.md`) — 38 GB cannot be committed — but it
means **the working tree's contents are a function of the branch, and any check that reads the
working tree is a check whose answer changes when you switch.**

## The class

This is the **third** time a missing input has turned a gate into a pass-shaped message in this
project:

1. **B2** — the vendor drift check `pytest.skip`ped when the study tree was absent, which on a
   product-only branch is every comparison forever. Fixed by shipping the pins as committed data.
2. **D25** — `cytune_e2e_composition_check.py` died on import for an entire release after a rename.
   A skipped test prints `s`; a script nobody invokes prints nothing.
3. **D34 (B1)** — the fleet gate, disabled on `dev` by a checkout, reporting `NOT RUN` in a colour
   nobody stops for.

Each was caught by *running the thing somewhere new*, never by reading it. The rule that follows,
and it is now in `docs/system/15_BRANCH_HAZARD.md`: **when a gate reports NOT RUN, find out why
before accepting it** — "the file is not on this branch" and "the file was deleted from your working
tree by the command you just typed" print the same line and mean very different things.
