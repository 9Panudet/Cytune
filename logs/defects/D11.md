# D11 — the confirmatory FLAT family was counted as a bare class, not the FM-flagged CELL (floor statistic wrong in both directions)

**Step:** P-2 boundary, A-3 authoring. **Date:** 2026-07-24. **Status:** fixed, validated
(revert-check + 7 tests green in X′; STATE + amendment corrected). **Raw:**
`results/fleet/fleet_ledger.jsonl` + `results/fleet/<kid>/class_v2.json`. Recompute:
`python3 scripts/phasep/template_analysis.py` → `confirmatory cell n: {'FLAT+FM': 11, 'MID': 18,
'LEVER-SEP': 23, 'INT': 37}`.

## Summary

PREREG §12 **A-2c** defines the confirmatory families verbatim as regimes
`{FLAT+FM, MID, LEVER-SEP, INT}` with "FLAT∧FM− is descriptive-only". The FLAT family is therefore
the **flagged cell** — measured `FLAT` *and* `flag_FM` — and `flag_FM` is an ORTHOGONAL flag
(A-2a), so `measured_v2` never takes the literal value `"FLAT+FM"`.

Three consumers counted the bare measured class instead:

1. `report_p2.build_report` — tallied `counts[e["measured_v2"]]` and then looked up `"FLAT+FM"`,
   rendering the confirmatory family as **0** while showing a separate `FLAT | 26 | OK` row. The
   confusion table's `FLAT+FM` column was all zeros for the same reason.
2. The `SYNTH_STAGE_COMPLETE` STATE entry and the synth-complete tick reports — reported
   "FLAT 26 ✓", concluding **2 of 4** confirmatory classes cleared the n=26 floor.
3. The campaign-completion summary presented at the boundary — same claim.

The error is **bidirectional**, which is why it was not self-cancelling: it credited 15 FM−
kernels to a floor they do not belong to, and it hid the 11 kernels that do. Truth: FLAT+FM = 11,
a shortfall of 15 — the **largest** of the campaign, larger than MID (+8) and LEVER-SEP (+3).
Corrected outcome: wave 1 cleared **1 of 4** confirmatory cells (INT 37), not 2 of 4.

## Root cause

A class label and a cell label share a name. `measured_v2 ∈ {FLAT, MID, LEVER-SEP, INT}` is the
primary strict-landscape partition; the confirmatory FAMILY `FLAT+FM` is the intersection of that
partition with an orthogonal flag. The string `"FLAT+FM"` is also the `intended_regime` value and
the generator's registry key, so it *looks* like a class everywhere it appears — and a lookup of
it against measured classes fails silently, returning 0 instead of raising.

Contributing: the intended-regime label `FLAT+FM` was already correct in the confusion table's ROW
index, which made the all-zero COLUMN read as a real (if surprising) measurement result — "the
FLAT+FM block never produced FLAT+FM" — rather than as a lookup miss. The block genuinely does
have a poor diagonal, which camouflaged the defect.

## Fix

`report_p2.py`: added `_cell(entry)` implementing A-2c verbatim, used for both the §1 floor table
and the §2 confusion columns; the FM− population is rendered as an explicitly non-confirmatory
row (`not confirmatory`), and the shortfall is reported with its size. Added the per-wave split
(A-3b) and the R1 FEAS contrast to the same table. Corrected `results/STATE_PHASEP.md` (new
`A3_execution` entry states the correction and supersedes the "FLAT 26 ✓" line) and recorded the
true cell n in the committed amendment (PREREG §12 A-3a) and memo. `run_fleet._cell_counts` — the
NEW consumer that decides when the A-3 top-up stops — was written cell-correct from the start and
carries its own regression test.

**No measurement, label, or table is affected.** Every `class_v2.json` was already correct;
`flag_FM` was measured and stored per kernel throughout. The defect was entirely in derived
counts.

## Validation

`test_report_p2.py` +4 tests: the flagged-cell count (2, not 0 and not 3), the descriptive row,
the confusion columns *and* the deliberate synth-vs-holdout population difference between §1 and
§2, the FEAS contrast, and an explicit non-vacuity test asserting the naive and correct counts
differ in both directions. **Failure path verified** — reverting only `_cell` to
`return e.get("measured_v2")` in a throwaway copy fails exactly 3 of 7; the fixed form passes 7/7
in X′.

## Lesson

Same shape as D10, one level up. D10: *ledger entries are events, not entities* — state the unit
of count. D11: **a measured class is not a confirmatory cell** — state the unit of MEMBERSHIP.
When a pre-registration defines a family as an intersection (class ∧ flag), every count of that
family must be computed by the intersection predicate, never by string-matching the family name
against a partition label — a name collision between an *intended* label and a *measured* label
makes the wrong lookup return 0 instead of failing loudly. Any figure that feeds a power floor
gets a test that asserts the naive computation would give a DIFFERENT answer (non-vacuity), because
a floor statistic that is silently 0 reads as "not populated yet", which is indistinguishable from
a legitimate early-campaign state. Caught while authoring A-3 against the amendment text verbatim
— i.e. by re-deriving the deliverable from the pre-registration rather than from the running
narrative. The F2 discipline in the ruling ("quote the cells VERBATIM, no silent substitution of
bare-class for flagged-cell") is exactly this lesson, and it found a live defect on first
application.
