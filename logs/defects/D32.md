# D32 — the documented directory-mode invocation crashed with a bare traceback

**Step:** launch pass, section D2 (senior power-user gate). **Date:** 2026-08-12.
**Status:** fixed, validated. **Found by:** a **senior power-user agent**, following
`docs/USER_GUIDE.md` §2.1 literally.
**Raw:** `src/cytune/session.py::Session.vendor`.
Recompute: `.venv/bin/python -m pytest src/cytune/test_cytune_contract.py -k d32`.

## Summary

```
$ cd multi && cytune tune . --driver driver.py --dry-run
[1/6] ingest — vendoring module + driver
shutil.Error: [('./.cytune/_kernels/.cytune/_kernels/.cytune/_kernels/… ×150 …',
                "[Errno 36] File name too long: …")]
```

`vendor` copytrees the module directory into the workspace. With the default `.cytune` workspace and
a module directory of `.`, the workspace is **inside** the tree being copied, so the copy recurses
into itself until the path exceeds `PATH_MAX`.

## Why it matters

This is not an exotic invocation. `docs/USER_GUIDE.md` §2.1 says *"Point cytune at a **directory**
instead of a file"*, and the default workspace is `.cytune`. **The guide's own default was a trap**,
and the user gets 150 lines of nested path and an errno rather than a sentence.

It is the same class as K-17 (an unhandled exception where a cytune-level message is promised), but
K-17 needs `chmod 500`; this one needs following the documentation.

## Fix

`vendor` refuses when the workspace is the module directory or inside it, naming both paths and
suggesting a workspace outside the tree. Checked before anything is copied, so a refusal leaves
nothing behind (the F11 rule).
