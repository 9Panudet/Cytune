# D20 — a cycle killed during the BUILD phase charged 0.0 s to the hard cap (the reconciler watched an artifact that never moves during a build)

**Step:** A-7 H-supply transition (stopping the pre-amendment H runner). **Date:** 2026-07-28.
**Status:** fixed, validated (4 new tests: 2 RED against the pre-fix reconciler, 2 non-vacuity
controls; plus the live re-charge of the killed H build).
**Raw:** `scripts/phasep/run_fleet.py::_reconcile_inflight`,
`scripts/phasep/test_d20_build_orphan.py`, survival ledger rows 2095 / 2099 / 2103. Recompute:
`podman run --rm --security-opt label=disable -v "$PWD":/w -w /w localhost/motifbo-tools:phase1
python3 -m pytest scripts/phasep/test_d20_build_orphan.py -q -p no:cacheprovider`.

## Summary

A-3d's hard cap is enforced against the append-only ledger, so a cycle killed before it can write a
row must still be charged. `_reconcile_inflight` does that by bounding the dead cycle's duration
from the newest mtime among the phase's continuously-written artifacts. It scanned the run log and
`table.jsonl`. **Neither advances during a build.** Every build-phase death therefore charged
`0.0 s`, and the cap could be overrun by an unbounded amount of real compile time without the
ledger ever seeing it. Fixed by scanning `build_manifest.jsonl` (the build's own per-config
progress file) and the `_so` directory as a backstop.

## Symptom

Stopping the pre-A-7 H runner at 01:59 to swap in the extended registries. The in-flight cycle
`fleet_MID_W2_200_mid_gatherpoly_r2` had been compiling since 01:32:13 — 27 minutes, ~1,620 s of
real rig time, with `_so/` visibly growing. Writing the in-flight marker and computing the bound
the committed reconciler would use:

```
marker written: {'kernel_id': 'fleet_MID_W2_200_mid_gatherpoly_r2', 't_start': 1785177133.7995477,
                 'log': 'results/fleet/run_fleet.log'}
log mtime - t_start = 0.0 s (the lower bound _reconcile_inflight will charge)
```

27 minutes of compiling would have been charged as zero.

## Root cause

```python
def _run(cmd, log):
    with open(log, "a") as f:
        f.write("\n$ " + " ".join(cmd) + "\n")
        f.flush()                                    # <-- the ONLY write until the child exits
        return subprocess.run(cmd, stdout=f, stderr=subprocess.STDOUT).returncode
```

`_run` writes the header, flushes, then hands the raw fd to the child. `build_phase.py`'s stdout
inside the container is **block-buffered** (not a tty), so its output reaches the file only when the
child exits or fills a 4 KiB block. Kill the child and the log's mtime is still exactly `t_start`.

The reconciler then did:

```python
for f in (rec.get("log"), os.path.join(out, rec["kernel_id"], "table.jsonl")):
    if f and os.path.exists(f):
        last = max(last, os.path.getmtime(f))
```

During a build, `table.jsonl` does not exist yet (CF-1: compile and measure never overlap) and the
log is frozen — so `max()` collapses to `t0` and `orphan_s` is `0.0`.

The docstring asserted the opposite and was believed rather than checked:

> Both phases write CONTINUOUSLY — gcc output into the run log, measured rows into table.jsonl

That sentence was the defect. It is true of the measure phase and false of the build phase, and the
measure phase is the one that got tested.

## Field evidence — this already happened, three times

Three of the seven wave-2 `CYCLE_ORPHAN` rows carry `orphan_s == 0.0` exactly:

| ledger row | kernel | charged | run that reconciled it |
|---|---|---|---|
| 2095 | `fleet_MID_W2_52_mid_hist_r2` | 0.0 s | 20260724T170021Z |
| 2099 | `fleet_MID_W2_52_mid_hist_r3` | 0.0 s | 20260724T175854Z |
| 2103 | `fleet_MID_W2_52_mid_hist_r3` | 0.0 s | 20260724T181328Z |

The other four (1,563.4 / 1,608.5 / 1,925.7 / 2,760.6 s) were measure-phase deaths and charged
correctly. `0.0` is the build-death signature.

### How much did A-3 undercharge?

**Not recoverable exactly** — those three kernel directories were resumed and completed on later
launches, which overwrote the mtimes that would have bounded the dead builds. What survives is an
**upper** bound per orphan: the interval between the end of the previous charged cycle in the
launching run and the run_id of the run that reconciled it.

| orphan | window | upper bound |
|---|---|---|
| `_r2` (161533Z launch, r1 cost 1,496.0 s) | ≈164029Z → 170021Z | ≤ 3,592 s |
| `_r3` (170021Z launch, r2 cost 3,113.2 s) | ≈175214Z → 175854Z | ≤ 400 s |
| `_r3` (175854Z launch, dup-skips only) | ≈175854Z → 181328Z | ≤ 3,274 s |
| | **total** | **≤ 7,266 s (≤ 2.02 h)** |

These are upper bounds, not estimates: the relaunch may have happened well after the death.

**Consequence, stated honestly.** A-3's recorded wave-2 spend of **175,406.8 s** is a LOWER bound.
True rig time is in **[175,406.8 , 182,672.8] s**, i.e. the overrun past the 172,800 s cap is
between **0.72 h and 2.74 h** rather than the recorded 0.72 h. Direction matters: an undercharge
makes the runner stop **late**, never early — so the cap was under-enforced, not over-enforced, and
no kernel was denied a cycle it was entitled to.

**No measured data is affected.** `orphan_s` feeds the cap gate and nothing else: not a table, not a
class label, not a property vector, not the freeze. The 129 frozen kernels are untouched. This is
an accounting defect, and it is carried into `P2_REPORT.md`'s envelope-actuals section as a bounded
interval rather than a point estimate.

## Fix

Scan the artifacts each phase actually writes:

```python
kdir = os.path.join(out, rec["kernel_id"])
for f in (rec.get("log"),
          os.path.join(kdir, "table.jsonl"),            # measure phase, one row per config
          os.path.join(kdir, "build_manifest.jsonl"),   # D20: build phase, one row per config
          os.path.join(kdir, "_so")):                   # D20 backstop: dir mtime per .so
    if f and os.path.exists(f):
        last = max(last, os.path.getmtime(f))
```

`build_manifest.jsonl` is the build's exact analogue of `table.jsonl` — `build_phase.py` appends one
row per compiled config. `_so/` is the backstop: a directory's mtime advances as each `.so` lands,
so it covers the window before the first manifest flush.

The docstring's false claim is replaced with the mechanism, and the reason is recorded inline so the
next reader does not re-derive it.

## Lesson

The pattern that hid this is the same one D16 hid behind: **a guard that fails silently open**. D16's
predicate could not execute and reported "nothing owed"; D20's reconciler found no evidence and
reported "nothing spent". Absence of evidence was read as evidence of absence in both.

The narrower lesson is about test coverage shape. `test_reconcile_inflight_charges_a_killed_cycle`
existed and passed — it seeded a stale log and asserted ~600 s was charged. It passed because it
wrote the log itself and back-dated `t_start` from it, which silently modelled the **measure** phase.
The build phase was never exercised. A cap has two phases and the test suite tested one; the
docstring claimed both. New rule for the cap machinery: **every phase that can burn rig time gets its
own death test**, and the artifact each test keys on must be one that phase genuinely writes.
