# D6 — motif.py warm-start loop missed the §8.3 two-stream seed refactor (stale `_propose` call-site)

**Step:** P3 code, pre-P3.3 deferred gate. **Date:** 2026-07-16. **Status:** fixed, validated.
**Commit:** fix in the A-2 execution commit following 3bbaae7. **Raw:** container pytest run
(24 passed / 1 failed → 44 passed after fix); repro command in Validation.

## Summary

The pre-registered deferred gate — "bo-math fixture set must re-run green in-container before
P3.3" — fired exactly as designed: `test_motif.py::test_motifbo_with_warmstart_respects_budget`
failed with `TypeError: _propose() missing 1 required positional argument: 'rf_state'` at
motif.py:143. When the bo-math-reviewer's required fix split BO's single RNG into two independent
streams (init/interleave rng + pinned RF `random_state`, §8.3), `bo._propose` gained a required
`rf_state` parameter. The Motif+BO warm-start loop reuses `bo._propose` but was not in the bo
fixture set, so its call-site kept the old 4-argument form.

## Root cause

Call-site drift across modules during a reviewer-mandated signature change, with test coverage
partitioned by module: the two-stream fix was validated against `test_bo.py` only, and the
in-container run of the full P3 suite was (legitimately, per CF-1) deferred while the pilot owned
the machine. The stale call-site was unreachable until a warm-started motifbo() run reached its
first non-random proposal step.

## Why the wrong fixes were rejected

Making `rf_state` optional (or passing the interleave `rng` into the RF) would compile — and would
silently reintroduce the exact one-RNG defect the bo-math-reviewer required fixed (surrogate
refits entangled with the exploration stream). The only faithful fix is deriving both streams in
motifbo the same way bo() does.

## Fix

`motifbo(sealed, budget, seed, warmstart_configs=None, hash_k=None, seed_i=None, alg_id=4)`:
streams via `bo._streams(seed, hash_k, seed_i, alg_id)`; `_propose(..., rng, rf_state)`; the
no-warmstart fallback forwards hash_k/seed_i/alg_id to bo(). alg_id=4 = Motif+BO's slot in §3.3's
fixed order (the study passes explicit values; the default serves unit tests).

## Validation

`podman run --rm --network=none --security-opt label=disable -v <repo>:/repo:ro
localhost/motifbo-env:phase1 bash -c "cd /repo/scripts/phasep && python3 -m pytest -q test_bo.py
test_replay.py test_motif.py test_a2_harness.py test_theta.py test_classify.py"` → **44 passed**.
No algorithm has touched any measured table (unit fixtures only); the defect never affected data.

## Why it slipped through / lesson

A reviewer-driven signature change is a cross-module event; its validation set must be "every
caller of the changed symbol" (grep/graphify the call graph), not the module's own tests. The
deferred-gate discipline caught it before the study — the gate exists precisely because
"green at commit time" was known to be partial (host could not run the container suite mid-pilot).
