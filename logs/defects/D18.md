# D18 — the verify stage never built its own inputs, so a pruned `.so` silently degraded a real 2× speedup to honest-flat

**Step:** P4-alpha CLI v0 riders, final transcript regeneration. **Date:** 2026-07-25.
**Status:** fixed, validated (live re-run + a third composition-check property with a red control).
**Raw:** `results/cli_v0/transcripts/smoke1_toy_quiesced.txt`,
`results/cli_v0/ws/toy_running_max/certificate.json`. Recompute:
`python3 scripts/cytune_e2e_composition_check.py`.

## Summary

`cytune`'s verify stage endpoint-measures the winner and the reference, but never ensured those two
configs were actually built. Because `table.jsonl` persists across runs, the winner can be a config
measured by an *earlier* run whose `_so` cache has since been pruned. The endpoint then reported
`not_built`, `confirm_winner` correctly refused to emit it, and the run fell back to the reference —
turning a genuine 2.0056× speedup into an `HONEST-FLAT` verdict. Fixed by building the verify set
before measuring it.

## Symptom

```
[5/6] verify — endpoint tier on the winner + the reference
      re-measured 2 configs at K=30, median-of-3
      WINNER REJECTED at endpoint: config 1294 — not_built: None
      fell back to the reference configuration. A config that fails the oracle is never emitted.

VERDICT: HONEST-FLAT
  Tuning ran but found only 1.0000x over the reference, below the 1.0200x bar this run could
  actually resolve ...
```

The same module, same rig, minutes earlier and later, certified **2.0056×**.

## Root cause

`src/cytune/cli.py` built configs at exactly two points — the probe set during ingest, and each DOE
batch during tune — and then called `sess.endpoint(verify_ids)` directly:

```python
verify_ids = sorted({winner, ref_id} | ...)
ep = sess.endpoint(verify_ids)["endpoints"]      # no build
```

The winner comes from `select_winner(sess.feasible_medians())`, and `feasible_medians()` reads
**every** row of `table.jsonl`, which is append-only and survives across runs. So the candidate set
at verify time is "everything ever measured in this workspace", while the set guaranteed to be
*built* is only "what this invocation compiled". Those two sets diverge the moment a cache is
pruned — which the D12 disk-discipline rule does routinely, and which this session did explicitly
before committing the smoke artifacts.

`worker._drop_stale_manifest_rows` (the D17 fix) correctly removed config 1294's stale manifest row,
so nothing claimed a false build. But nothing then rebuilt it, because 1294 was not in this run's
probe set and this run's DOE walk selected different candidates.

## Why it produced the symptom

`campaign._manifest(out)` had no row for 1294, so `worker.cmd_endpoint` took its `not_built` branch
and returned `feasible: False`. `plan.confirm_winner` treats any non-confirmed winner as refused —
correct and deliberate, since a config that cannot be verified must never be emitted — and returned
the reference. The certificate then compared the reference against itself, produced a 1.0000× ratio,
failed the emit margin, and rendered the honest-flat verdict.

Every safety mechanism behaved exactly as designed. The failure is that a **build gap wore the
costume of an oracle rejection**: the user is told the landscape is flat when in fact the tool
declined to re-verify its own winner.

## Fix

`src/cytune/cli.py`, before the endpoint call:

```python
sess.build(verify_ids)      # idempotent; rebuilds anything stale (D18)
ep = sess.endpoint(verify_ids)["endpoints"]
```

The verify stage now guarantees its own inputs, rather than assuming an earlier stage happened to
produce them. Combined with D17's stale-row drop, a pruned cache is transparently rebuilt.

Separately, the rejection is now recorded in the **certificate** (`winner_rejection`) instead of
only being printed. A refusal is a correctness-relevant event; an auditor reading the artifact must
be able to see that one occurred and why.

## How it was found

Regenerating the report's smoke-1 transcript so it would agree with its certificate. The run had
been executed three times that hour; only the run that followed a cache prune *and* whose DOE walk
did not re-select the previous winner hit the gap.

## Why it slipped through

**Workload gap, one layer deeper than D17.** D17 covered "the manifest claims a build that is
gone". This is "nothing claims the build at all, and nobody asked for it". Neither is reachable
until a workspace is reused across a prune, and every earlier run either started clean or reused an
intact cache. The composition check that eventually exposed the class of bug was itself written
after both defects were introduced.

## Validation

- Live re-run of the same module in the same pruned workspace: `VERDICT: IMPROVEMENT`,
  **2.0056×**, `re-measured 2 configs at K=30` with no rejection.
- `scripts/cytune_e2e_composition_check.py` gains a third property — *a winner refusal must be an
  oracle/measurement event, never `not_built`* — with an unconditional **red control** that plants
  a `not_built` refusal and requires it to be caught.
- Full suite: 102 passed, 1 skipped, in `motifbo-env:phase1`.

Validated for the pruned-cache path. Not validated for a workspace whose `table.jsonl` references a
config from a *different module* — that cannot arise, since each session owns its own workspace
subdirectory.

## Action items

- The certificate now carries `winner_rejection`; the P-2 report's CLI section should note that a
  refusal is auditable from the artifact alone. Done.
- Consider whether `feasible_medians()` should be scoped to the current run's configs rather than
  the whole table. Not changed in v0: reusing prior measurements is correct and saves real time; the
  build guarantee is the right place to fix the gap. Open as a design note.
