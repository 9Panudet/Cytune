# D22 — the report generator hardcoded a DECISION MEMO's threshold and cited it as the pre-registration

**Step:** P-2 checkpoint report (task #63, audit battery). **Date:** 2026-07-30.
**Status:** fixed, validated (rule deleted from code; report regenerated; the corrected floors
change the checkpoint's headline conclusion).
**Found by:** `stats-auditor` (verdict FAIL), not by me.
**Raw:** `scripts/phasep/report_p2.py` §1/§4, `results/prereg/PREREG_PHASEP.md:265-278`,
`results/pilot/A2_DECISION_MEMO.md:400`, `results/fleet/P2_REPORT.md`.
Recompute: rerun `python3 scripts/phasep/report_p2.py`; the n's derive from the frozen ledger.

## Summary

`report_p2.py` §4 applied this rule to the agreement watch:

```python
fired = frac > 0.10          # ">10% agreement failures => measurement-auditor investigation"
```

and the report attributed it to the pre-registration, labelled `B_02`. **`B_02` does not occur
anywhere in `PREREG_PHASEP.md`.** `grep -c "B_02" results/prereg/PREREG_PHASEP.md` returns **0**.
The string is from `results/pilot/A2_DECISION_MEMO.md:400` — a decision memo, i.e. a document that
records a choice, not a document that binds one.

The ACTUAL pre-registered rule, PREREG §4, is a different rule with a different consequence and
**no threshold at all**:

> a kernel failing the binary check is flagged `agreement_fail`; … at P-2/fleet it is **excluded
> from per-class inference (moved to descriptive-only)** and the count is presented at the P-2 STOP
> (so the human approves a rule, not a case-by-case call).

## Symptom

The checkpoint report stated **2 of 3 confirmatory floors MET**. Under the rule that was actually
pre-registered it is **0 of 3**:

| cell | n as-measured | agreement_fail | n conformant | vs floor 26 |
|---|---|---|---|---|
| FLAT+FM | 20 | 0 | 20 | below by 6 (was already below) |
| MID | 26 | 2 | **24** | below by 2 — the whole gap is the exclusion |
| LEVER-SEP | 26 | 6 | **20** | below by 6 — the whole gap is the exclusion |
| INT | 41 | 11 | **30** | OK |

Two cells that read "MET" read MET only because 8 kernels the prereg excludes from inference were
counted in their n. Exact power at the conformant n (committed generator, N_SIM=60,000,
SEED_EXT=20260628, δ=0.4): 0.708 / 0.776 / 0.708 / 0.862 — against the 0.80 target.

Every "2 of 3 floors met" statement made since the A-3 cap-stop is wrong.

## Root cause

Two distinct failures, and the second is the one that matters.

1. **A memo string was hardcoded as a prereg citation.** The threshold entered `report_p2.py` as a
   literal with a comment naming `B_02`, and no step in the pipeline ever checked that `B_02`
   resolves to anything in the prereg. Nothing in the repo cross-references citation labels
   against `PREREG_PHASEP.md`, so a wrong citation is invisible until a human greps for it.
2. **The report generator was never treated as an instrument.** Every measurement instrument in
   this campaign — the generator, the replay harness, the delta probe — is required to have
   positive and negative controls before its readings count (CLAUDE.md, "New instruments"). The
   report generator produces the numbers a human signs off on, which makes it an instrument by
   the same definition, and it had no controls: no test asserted that a floor verdict changes when
   an `agreement_fail` kernel is added, and `test_report_p2.py` did not cover §1's floor logic at
   all. A rule that is wrong in the generator is wrong in every report it emits, silently and
   consistently — which reads as stability, not as error.

This is the **proxy-as-prereg** defect class, and it is the sibling of D5 (compare against a
contaminated number) and D21 (compare two numbers that share a name). All three are the same shape:
a token that *looks* like the authority — a v1 field name, a memo label — standing in for the
authority, with nothing in the pipeline forcing the substitution into the open.

## Fix

1. The threshold is **deleted from the code**. `fired = frac > 0.10` no longer exists in
   `report_p2.py`; it governs nothing. It is recorded once, as history, in
   `DEVIATIONS_REGISTER.md`.
2. `_conformant(e)` implements §4 verbatim and unconditionally. §1's floor verdict, §1's power
   column, and §1c's FEAS-arm n are all computed on the conformant set. The as-measured n is still
   printed beside it, so the size of the exclusion is visible rather than absorbed.
3. `run_fleet._cell_of` is now the single definition of the confirmatory cell, imported by
   `report_p2.py` and `exact_power.py`. Three copies of the A-2c rule existed; D11 was caused by
   exactly that duplication.
4. `_cell_counts(..., conformant=True)` carries the rule into the power computation, so the
   reported power is the power of the inference that will actually be run.
5. The measurement-auditor referral for the agreement failures is now **unconditional**. §4's
   exclusion answers the INFERENCE question; it does not answer whether the failures are a rig
   fault, and that question was previously gated behind the memo's threshold — i.e. the referral
   existed only because the wrong rule happened to fire.

## Validation

- `grep -c "B_02" results/prereg/PREREG_PHASEP.md` → `0` (the citation resolves to nothing).
- `sed -n '265,278p' results/prereg/PREREG_PHASEP.md` → the §4 text quoted above, verbatim.
- Regenerated report reads **0 of 3 confirmatory cells meet the floor**, with the exclusion count
  shown per cell.
- `scripts/phasep/test_report_p2.py` gains the control this section says was missing: a fixture
  where flipping one kernel's `agreement_ok` to `False` must move a cell from OK to BELOW FLOOR.
  Without that assertion the fix is untested and could regress in exactly the same silent way.

## Lesson

**A report generator is an instrument, and a citation is a claim that has to resolve.** Two guards
follow, both cheap:

- Any rule in code that cites a pre-registration must name a string that can be grepped in
  `PREREG_PHASEP.md`, and something must actually grep it. A citation nobody can resolve is a
  citation nobody checked.
- A rule with a threshold, applied to our own headline result, is where to look first when the
  result is more favourable than the raw data suggests. This one converted 0/3 into 2/3 — in the
  direction that made the checkpoint look ready.

The favourable-surprise discipline exists for this ("favourable surprises are alarms"). It did not
fire here because the surprise was not surprising: the report said what I expected it to say.
