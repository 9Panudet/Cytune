# D31 — the certificate stated that a flag the user typed was not typed, about floating-point consent

**Step:** launch pass, section D2 (senior power-user gate). **Date:** 2026-08-12.
**Status:** fixed, validated (positive and negative control).
**Found by:** a **senior power-user agent** evaluating cytune for CI adoption.
**Raw:** `src/cytune/certify.py`, the FLOATING-POINT CONSENT block.
Recompute: `.venv/bin/python -m pytest src/cytune/test_cytune_render.py -k d31`.

## Summary

With a `.cytune.toml` present and `--allow-fp-contract` typed on the command line:

```
rendered: FLOATING-POINT CONSENT: opted in via --allow-fp-contract; emitted semantics = contract
            NOTE: that opt-in did NOT come from the command line you typed. It came from the
            source named above — check it if you did not intend to relax floating-point semantics.

json:     .effective_config.provenance.allow_fp_contract == "command line"
```

The same document says the opt-in came from the command line and that it did not.

## Root cause

```python
if any(w and w not in ("command line", "built-in default") for w in srcs.values()):
```

`srcs` holds the provenance of **both** FP flags. A config file that merely *mentions*
`allow_fast_math = false` gives that key a file provenance — so the `any()` fired on a flag the user
never opted into, and the note was printed about the flag they had just typed.

Only the flags actually **opted into** can say anything about where the opt-in came from.

## Why it matters more than a wording slip

`docs/GUARANTEES.md` **G7** promises that a certificate contradicting itself is never emitted, and
names its own precedent: *R2 — `--allow-fast-math` emitted `-ffp-contract=fast` while the JSON field
denied it.* This is that class, on the same block, un-caught.

It also cries wolf on the one warning a reviewer is meant to trust. A note that fires spuriously is
worse than no note: the next time it appears on a run where the opt-in really did come from a
checked-in file, it will be read as noise.

The agent found a second-order harm: the note ends *"It came from the source named above"*, but the
`SETTINGS IN EFFECT` block that names sources prints only under `--explain`. On a run without it,
the note points at a block that is not in the document.

## Fix

Test the provenance of the opted-into flags only.
