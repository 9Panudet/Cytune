# D16 — `graphify_drain.sh` failed OPEN: reported "nothing owed" while a campaign cycle was live

**Step:** P4-alpha, F1 quiesce fix (Amendment A-4h). **Date:** 2026-07-25.
**Status:** fixed, validated (commit `510a203`; caught by its own test while being written).
**Raw:** `scripts/hooks/graphify_drain.sh`, `scripts/hooks/test_graphify_gate.py`. Recompute:
`podman run --rm -v "$PWD/scripts":/w/scripts:Z -w /w --network=none localhost/motifbo-tools:phase1
python3 -m pytest scripts/hooks/test_graphify_gate.py -q`.

## Summary

The drain script that pays off deferred graph rebuilds is required to refuse while a campaign
build/measure cycle is live (CF-1 quiesce-all). It resolved its repo root via `git rev-parse` with
no fallback; in any environment without `git` — which includes **both pinned container images** —
the path came out empty, the busy predicate could not be executed, the failure was swallowed, and
the drain concluded the box was idle and reported "nothing owed". A safety check that cannot run
must refuse, not assume. Fixed by deriving the path from the script's own location and failing
**closed**.

## Symptom

`test_drain_refuses_while_a_cycle_is_live`, run inside `motifbo-tools:phase1`:

```
AssertionError: drain should refuse (2), got 0: graphify_drain: nothing owed.
  stderr: graphify_drain.sh: line 7: git: command not found
```

The fixture had an in-flight marker present and a non-empty debt queue. The correct behaviour is
exit 2 with `REFUSING`; the observed behaviour was exit 0 with `nothing owed`.

## Root cause

```sh
repo="$(git -C "$(dirname "${BASH_SOURCE[0]}")" rev-parse --show-toplevel)"   # no fallback
queue="$repo/graphify-out/.graphify_deferred"
if why="$(bash "$repo/scripts/hooks/campaign_busy.sh" 2>/dev/null)"; then ...
```

Two failures compounded:

1. **No fallback on `repo`.** `campaign_busy.sh` and `graphify_gate.sh` both used
   `... || echo .`; the drain did not. With `git` absent, `$repo` became the empty string.
2. **Fail-open on the predicate.** With `$repo` empty the command became
   `bash /scripts/hooks/campaign_busy.sh`, which does not exist. Bash exits non-zero, `2>/dev/null`
   discarded the message, and the `if` treated non-zero as **IDLE** — the same branch a genuine
   "no cycle running" answer takes. The script could not distinguish "predicate says idle" from
   "predicate did not run".

`set -uo pipefail` did not help: `-u` catches unset variables, not variables set to empty by a
failed command substitution, and `-e` was deliberately absent.

## Why it produced the symptom

With `$repo` empty, `$queue` resolved to `/graphify-out/.graphify_deferred`, which does not exist,
so `[ ! -s "$queue" ]` was true and the script printed "nothing owed" and exited 0 — the *success*
path. The consequence in production would be worse than a wrong message: the drain runs
`graphify update`, an AST rebuild across the repo, and it would have launched that during a timed
measurement phase. That is precisely the host-load contamination CF-4/D5 exist to prevent, and it
would have been introduced by the tool written to prevent it.

## Fix

`scripts/hooks/graphify_drain.sh`:

```sh
repo="$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)"   # location-derived, no git needed
busy="$repo/scripts/hooks/campaign_busy.sh"
if [ ! -r "$busy" ]; then
    echo "graphify_drain: REFUSING — cannot read the busy predicate at $busy (failing closed)."
    exit 2
fi
```

`scripts/hooks/campaign_busy.sh` got the same location-derived resolution, replacing its
cwd-dependent `|| echo .` — a caller's working directory must never change whether the box reads
busy.

Fail-closed is the correct default here because the costs are asymmetric: a needlessly deferred
graph rebuild costs seconds, while a rebuild launched during a measure phase can invalidate a
kernel's entire 1,728-config table.

## How it was found

By the test written for the fix, before the fix shipped. The gate work (A-4h) added
`test_drain_refuses_while_a_cycle_is_live` as a normal branch test; running the suite inside the
pinned image — where `git` is absent — exposed the fallback gap immediately. Running it on the host
would have passed and hidden the defect, since the host has `git`.

## Why it slipped through

**Environment assumption never stated.** The scripts were written on a host with `git` on `PATH`
and were assumed to run there. `graphify_drain.sh` is genuinely host-side, so the assumption was
*almost* right — but the tests are not, and neither pinned image ships `git`. The container run is
what turned an unstated assumption into a visible failure.

## Validation

- `test_drain_refuses_while_a_cycle_is_live` — exit 2, `REFUSING`, with an in-flight marker.
- `test_drain_fails_closed_when_the_busy_predicate_is_unavailable` — exit 2 with `failing closed`
  when the predicate is deleted; this is the regression test for the fail-open itself.
- Both branches of the gate also covered: `test_gate_queues_the_debt_and_swallows_the_rebuild_when_busy`
  and `test_gate_falls_through_to_the_rebuild_when_idle`.
- 7 tests green in `motifbo-tools:phase1`; the live-hook guard check passes on the host.

Validated in the no-`git` environment (containers) and the with-`git` environment (host).
