# D25 — the composition-level E2E check has not run since the `_phasep` → `_vendor` rename

**Step:** launch pass, B2/B4 (standing gates). **Date:** 2026-08-12.
**Status:** fixed, validated (runs green on current code, red on reconstructed pre-fix behaviour).
**Found by:** reading `scripts/cytune_e2e_composition_check.py` while enumerating what the path
registry (B4) should absorb. Not by any test, gate, or run — **nothing was watching it.**
**Raw:** `scripts/cytune_e2e_composition_check.py:30`.
Recompute: `.venv/bin/python scripts/cytune_e2e_composition_check.py --artifacts-only`.

## Summary

```
ModuleNotFoundError: No module named 'cytune._phasep'
```

Line 30 read `from cytune._phasep import theta`. The package renamed that subpackage to `_vendor`
at 1.0.0. The script therefore died **on import**, before its first check, and had done so for
every invocation in the interval.

## What was lost while it was dead

The script's own docstring states why it is not a pytest:

> Both defects are properties of the WHOLE PIPELINE's output, and both were invisible to unit tests
> of the parts: every component was individually correct and the composition was dishonest.

It carries four composition properties, each with a **red control** proving the check discriminates:

| id | property | red control |
|---|---|---|
| D13 | a flat verdict emits the reference | pre-fix behaviour (flat route → `verdict=improvement`) is CAUGHT |
| D14 | every emitted FP-affecting flag is disclosed | an undisclosed `-ffp-contract=fast` is CAUGHT |
| D18 | a winner refused for `not_built` is reported as an orchestration failure | reconstructed refusal is CAUGHT |

Those are three of the four defects in the class *"the unit is tested, the composition models fewer
cases than production has"* — the class D-3 was the fourth instance of. **The instrument built to
watch that class was itself absent from every gate that claimed to include it.**

## Root cause

A rename with no consumer inventory. `_phasep` → `_vendor` updated the package and the tests; a
host-side script outside `src/cytune/` and outside `pytest` had no mechanism that would notice.

The deeper cause is the one D23 already named and this project had not yet pointed at itself:
**a check that never runs leaves no trace.** A skipped pytest at least prints `s`. A script nobody
invokes prints nothing at all, and its absence is indistinguishable from its success.

## Why nothing caught it

1. **Not collected by pytest.** By design — it spawns podman, and the container has no podman.
2. **Not in `smoke.sh`.** The pre-tag ritual ran doctor/init/tune/audit/resume/binding and never
   this. So the one gate that runs host-side scripts did not run this host-side script.
3. **Not in the reachability walk.** `test_cytune_architecture.py` walks `src/cytune/`;
   `scripts/` is outside it.
4. **No import check anywhere.** Nothing in the repo asserts that a committed script can be
   imported, so a dead import is invisible until somebody types the command.

Four independent mechanisms, none of which covered the case, and the file sat between all of them.

## Fix

`scripts/cytune_e2e_composition_check.py:30` — `_phasep` → `_vendor`, with the history recorded at
the import site rather than in a commit message nobody will read again.

`scripts/release/smoke.sh` — the composition check now runs in **step 0**, in `--artifacts-only`
mode, so the pre-tag ritual exercises it without paying for a second podman campaign. That closes
gap (2), which is the one that matters: the check is now inside the gate that has to pass before a
tag.

## The class, and what actually changed

D25 is **not** the "unit tested, composition untested" class it was written to defend. It is the
class *above* it: **the defence itself was not verified to be running.**

The launch pass produced two mechanisms in this family, and it is worth being precise about which
one covers what, because neither covers the other:

- **B2 (vendor manifest)** — the drift check used to `pytest.skip` when the study tree was absent,
  which on a product-only branch is every comparison forever. Now it compares against committed
  data and cannot skip.
- **B4 (path registry)** — the composition sweep now fails when a registered production path was
  never exercised.
- **D25 (this one)** — a *script* that could not import at all.

**The general defence was built rather than deferred**, because the instance fix (put this script
in `smoke.sh`) leaves every sibling unguarded, and "one script was renamed out from under its
imports" is obviously not a one-off.

`tests/test_script_imports.py` parses **every** committed `scripts/**/*.py` and asserts that each
`cytune.*` name it imports still resolves against the package. 122 checks; it carries the real
defect as its positive control (`cytune._phasep` must read as missing while `cytune._vendor.theta`
reads as present) and a negative control so a legitimate re-export like
`from cytune._vendor import designs_path` is not a false alarm — that resolver bug was found by
running it, three scripts deep, before this file claimed the check worked.

Static rather than executing each script, deliberately: most of these import numpy or sklearn or
the study tree and several do work at module scope, so importing them all would fail for reasons
that are not drift. What D25 *was* is fully decidable by parsing.

Still open, stated plainly: this covers `cytune.*` imports only. A script that breaks because a
**third-party** API moved, or because a function it calls changed signature, is not covered by
anything here.
