# D17 — build resume trusted `build_manifest.jsonl` alone; a pruned `_so` cache produced "built 17/17" then a raw ImportError

**Step:** P4-alpha CLI v0 riders, composition-check authoring. **Date:** 2026-07-25.
**Status:** fixed, validated (4 unit tests + the live E2E run that exposed it now passes).
**Raw:** `results/cli_v0/transcripts/composition_checks.txt` (pre-fix failure captured in the first
run of that script). Recompute: `python3 scripts/cytune_e2e_composition_check.py`.

## Summary

`cytune` resumes a workspace by reading `build_manifest.jsonl` and treating any config with a
manifest row as already built. It never checked that the corresponding `.so` still existed. After
the smoke workspaces had their `_so`/`_ccache` directories pruned (D12 disk discipline), a re-run
reported `built 17/17 configs` and then died inside `measure_child` with an unhandled
`ImportError`. Fixed by dropping manifest rows whose `.so` is missing, so they rebuild.

## Symptom

First live run of `scripts/cytune_e2e_composition_check.py`:

```
[1/6] ingest — vendoring module + driver
      building the reference config + probe design ...
      built 17/17 configs
      capturing golden output + deriving the oracle ...

cytune: golden failed (rc=1): calibrate: reference measure failed: le_from_spec(spec)
  File "<frozen importlib._bootstrap_external>", line 1289, in create_module
ImportError: /work/pilot_C_01/_so/kernel_288.so: cannot open shared object file: No such file or directory
```

The `built 17/17` line and the missing-`.so` error are two statements about the same 17 configs.

## Root cause

`scripts/phasep/campaign.py::build_all` resumes like this:

```python
done = set()
if os.path.exists(mpath):
    for l in open(mpath):
        done.add(json.loads(l)["config_id"])
todo = [c for c in config_ids if c not in done]
```

Membership in the manifest is the sole liveness test. The manifest is append-only and durable; the
`_so` directory is neither — it is a build cache, gitignored, and routinely deleted.

The assumption is **sound inside the study**: a fleet kernel's `_so` is pruned only after its
`table.jsonl` and `class_v2.json` are complete and committed, and such a kernel is never rebuilt or
re-measured. It is **unsound for a product workspace**, which a user, a disk cleanup, a tmpfs
reboot, or the D12 steward prune rule can empty at any time while the workspace is still live.

## Why it produced the symptom

`build_all` skipped all 17 configs and returned the manifest's own `n_ok` count, so the CLI
truthfully reported what the manifest said. `campaign.calibrate` then read `ref["so_path"]` from
that manifest and handed the stale path to `measure_child`, which called
`importlib.util.spec_from_file_location(...)` on a file that no longer existed. The error surfaced
three stages downstream of its cause, as an import failure inside a subprocess, with no mention of
the build phase.

## Fix

`src/cytune/worker.py::_drop_stale_manifest_rows`, called at the top of `cmd_build`: rewrite the
manifest without any row that claims `ok` but whose `so_path` is gone, then let `build_all` rebuild
them normally. The count is surfaced as `stale_rebuilt` in the build result.

Rows with `ok: false` are **kept deliberately** — a cythonize failure is cached as feasibility-0 by
the inherited β policy, and dropping it would silently re-attempt a build the study deliberately
records as failed.

**Fixed in cytune, not in `campaign.build_all`.** `campaign.py` is the operative study path with a
paused campaign about to resume against it; the failure mode is not reachable there (pruning only
targets completed kernels), so editing it would be risk without benefit. The asymmetry is recorded
in the fix's docstring so the next person does not "helpfully" push it upstream.

## How it was found

Writing the D13/D14 composition checks, which re-run the pipeline live. The workspaces they targeted
had been pruned an hour earlier when the smoke results were committed. The check found a defect it
was not written to look for.

## Why it slipped through

**Workload gap.** Every prior run either built from empty (first smoke) or resumed against an intact
cache (the immediate re-runs). The prune step ran only at commit time, after the last run. The first
resume across a prune was the first execution of this path — and it happened one hour later.

## Validation

- `src/cytune/test_cytune_worker.py`: 4 tests — stale row dropped, failed-build row kept, intact
  manifest not rewritten (byte-identical), missing manifest not an error.
- Live: `scripts/cytune_e2e_composition_check.py` re-runs both cases end to end against the pruned
  workspaces and now rebuilds and completes; all 4 composition checks pass.
- Full suite: 82 passed, 1 skipped, in `motifbo-env:phase1`.

Validated for the pruned-`_so` case. Not validated for a *partially* pruned cache with a corrupted
(rather than absent) `.so` — an unreadable-but-present file would still be trusted.

## Action items

- Filed as a known gap: a present-but-corrupt `.so` is not detected. Not fixed in v0; a size/hash
  check on resume would close it. Recorded in `CLI_V0_REPORT.md` §7.
- No change to `campaign.build_all`; the study path is unaffected and deliberately untouched.
