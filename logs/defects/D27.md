# D27 — the sanitizer gate's CHECKS and its LICENCE keyed on different fields

**Step:** launch pass, section D4 (hacker regression against the binding layer). **Date:** 2026-08-12.
**Status:** fixed, validated (14 tests, including the adversary's exact D-3 replay).
**Found by:** an **adversarial agent** whose only instruction was to produce a false certificate.
**Raw:** `src/cytune/certify.py::gate_is_trustworthy`, `binding.py:314,318`, `coherence.py:127`.
Recompute: `.venv/bin/python -m pytest src/cytune/test_cytune_gate_trust.py`.

## Summary

Every check on the gate was conditioned on `gate["ran"]`. Every licence granted by the gate was
conditioned on `gate["clean"]`.

| what | condition | site |
|---|---|---|
| I4.3 — does the gate describe the emitted config? | `if gate.get("ran") and …` | `binding.py:314` |
| I4.3 — does it name the same source tree? | `if gate.get("ran") and …` | `binding.py:318` |
| I1.4 — does the gate describe the emission? | `if gate.get("ran") and …` | `coherence.py:127` |
| **`safety_wording_earned`** | **`clean is True`** | `certify.py:944` |
| **`--apply`** | **`clean is not True`** | `apply.py:47` |

A gate carrying **`ran=False, clean=True`** therefore fell in the hole between them: nothing checked
which configuration it described, and everything licensed it.

The adversary used it twice:

```
emitted config_id=0   gate.config_id=7   gate.ran=False   gate.clean=True
cert.sanitizer_gate_ran=False    cert.safety_wording_earned=True
rendered: "CLEAN — config 7 was rebuilt under ASan+UBSan and ran with no report."
--apply: WOULD WRITE THE HEADER
```

and then, worse:

```
emitted=288 (the reference), gate.config_id=0 (the REJECTED candidate)
rendered: "EMIT: the reference configuration (unchanged) is the best safe choice."
          "CLEAN — config 0 was rebuilt under ASan+UBSan and ran with no report."
```

**That second one is D-3 exactly** — the reference emitted while carrying the demoted candidate's
verdict — reached through a different door than the one D-3 came through and closed.

## The sibling finding, in the same family

`gate["authoritative"]` was written in three places (`binding.py:328,338`, `sanitize_gate.py:188`)
and **read in none**. `binding.py:327-332` sets it False when a gate does not attest which source
tree it built, and embeds a warning string *into the certificate*:

> "…the 'safe' wording is withheld and `--apply` refuses."

Both halves of that sentence were false in the same document that carried it. `safety_wording_earned`
and `apply.check_applicable` both keyed on `image_overridden`, which that branch does not set.

The test that appeared to cover it — `test_a_gate_that_omits_its_source_attestation_is_not_
authoritative` — asserted the flag was False and stopped. **It tested the flag and never the
consequence the flag's own warning promised.** That is the vacuous-test shape, on the fix for a
previous adversarial finding.

## Root cause

One question — *may this gate result license a safety claim?* — answered in four places, in two
different vocabularies. Nothing forced them to agree.

## Fix

`certify.gate_is_trustworthy(g)` is now the single predicate, and the only one:

```python
return bool(g.get("clean") is True
            and g.get("ran") is not False          # a gate that did not run cannot be clean
            and not g.get("image_overridden")      # H6
            and g.get("authoritative") is not False)  # it attested its source tree
```

Used by `certify.safety_wording_earned`, by coherence I1.6, and by `apply.check_applicable`.

`is not False` rather than truthy, deliberately: gates from the ordinary path never set
`authoritative` at all, and treating absence as failure would refuse every clean run. A test pins
that distinction.

## What was NOT fixed, and why

The same adversary produced two further findings that are recorded in `docs/KNOWN_ISSUES.md`
(K-12, K-13, K-14) rather than fixed:

**C1's noise floor is estimated from the driver's own wall clocks** (K-12). A driver whose reported
wall clocks are noisy enough inflates σ, inflates the budget, and trips the no-power cutoff — the
speedup is then certified with `NOT CHECKED` beside it. Demonstrated: a certified `IMPROVEMENT
2.000x` on a kernel whose true speedup was 1.000×.

Not fixed **because changing the C1 budget changes verdicts**, and every number in
`results/release/LAUNCH_REPORT.md` was measured with the current formula. `docs/CONTRIBUTING.md`
sets the bar for an engine change — pre-registration, offline evaluation, the fleet gate — and
shipping one on an adversary's say-so would be the shortcut this project exists to refuse.

What *was* fixed is the false sentence. The certificate's attestation claimed C1 "catches ANY
claimed speedup on a kernel that is really flat". It now states the limit, including that a noisy
driver can disarm the check.

## Class

**"Two predicates for one question."** Related to but distinct from D-3's "the composition models
fewer cases than production has": here the composition was complete, and the two halves of it
disagreed about what they were testing for.

The defence is narrow and honest: one predicate, with a test asserting its consumers call it. There
is no general mechanism preventing a future check from inventing a fifth condition — that would need
a way to enumerate "questions the codebase answers", which does not exist.

## What the adversarial pass says about testing

D26 and D27 were both found in under an hour by agents with no stake in the answer, on a codebase
with 900+ tests and four standing gates. Neither was reachable by reading the code with the
intention of confirming it works.

The specific lesson from D27 is narrower and sharper: **a test that asserts a flag is set, without
asserting the consequence the flag promises, is not coverage.** The flag was set. The warning was
written. Nothing read either.
